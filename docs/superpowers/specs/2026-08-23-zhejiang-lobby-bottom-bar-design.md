# 浙江游戏大厅首页底栏替换设计

> 后续修正：商城完整默认帧和浙江原版快速开始以 `2026-08-23-zhejiang-lobby-store-quick-start-design.md` 为准；该修正取代本文“移除快速开始”的早期决定。

## 1. 背景与目标

当前 `android` 首页通过一张 `2440×285` 的 `lobby_bottom_controls.png` 同时绘制商城、分享、战绩、消息、设置、更多等内容，并额外叠加 `lobby_quick_start.png`。这些视觉元素大部分不是独立控件，且样式来自闲逸斗地主，与首页所参考的浙江游戏大厅不一致。

本次改造采用 `/Users/mosc/Downloads/逆向/浙江游戏大厅/原版可编辑源码/热更新工程` 中最新普通大厅底栏，而不是 APK 内置旧版底栏，也不是 `NewGoldHall` 金币大厅底栏。

成功标准：

1. 首页底部显示浙江大厅最新普通大厅的圆角深棕底栏。
2. 默认入口顺序严格为：商城、装扮、战绩、活动、分享、背包、邮件、更多。
3. 八个入口均为独立点击控件，不再依赖整张底部截图承载交互。
4. 点击“更多”显示浙江大厅同风格的二级菜单，再次点击或点击菜单外区域关闭。
5. 移除闲逸斗地主样式的旧底栏、旧更多弹层和旧快速开始按钮。
6. 首页背景、顶部信息、公告、活动卡片、游戏卡片、好友面板和台州麻将入口保持不变。
7. 在 1920×1080 虚拟坐标下布局正确，并继续兼容项目现有的横屏缩放方式。

## 2. 原版证据与复用范围

采用的原版实现：

- `热更新工程/src/lobby/Modules/Lobby/View.lua`
  - `initBottomLeftUI()` 创建普通大厅底栏。
  - 底栏原始尺寸为 `2 × 10 + 8 × 160 = 1300`，高度 `95`。

  - “更多”从底栏中的 `GENG_DUO` 节点展开二级菜单。
- `HorizontalMenuBarEx.lua`

- `configure/Common/LobbyIconListConfig.json`
  - 普通大厅底栏 `MenuBarID = 3`。
  - 入口顺序为 `1001, 1027, 1005, 1002, 1017, 1021, 1018, 1007`，分别对应商城、装扮、战绩、活动、分享、背包、邮件、更多。
- `hall/Image/lobbyNew/_Plist.plist/.png`
  - `Img_dl.png`：原始 `150×95` 的圆角深棕底板切片。
  - `Img_fgx.png`：原始 `1×42` 的分隔线。
  - `Img_redpoint.png`：原始 `33×33` 红点。
  - `Img_tip_di.png`：更多菜单的气泡底板切片。
  - `Img_x.png`：装扮入口的“新”标记。

由于当前首页是原生 Java UI，不能直接执行 Cocos Lua、CSB 或 Spine。复用定义为：复用原始图像内容、入口数据、顺序、尺寸、间距、字体视觉参数、红点语义和展开逻辑；使用当前项目的 `BoxRoot` 和原生 Android 控件等价渲染。

## 3. 方案比较与选择

### 方案 A：原生独立控件复刻（采用）

从浙江原版图集中提取底板、分隔线、红点和更多菜单底板；在 Android 中创建八个独立入口。布局数据放入纯 Java 模型，`MainActivity` 负责渲染和点击行为。

优点：视觉与行为均可还原；入口可测试、可访问；无需增加 Cocos 或 Spine 依赖；修改范围可控。

限制：商城 Spine 动画不能原样播放，需将原始纹理组合成静态商城图标。

### 方案 B：生成一张新的浙江底栏整图并覆盖点击区

将浙江素材预合成为一张 PNG，再用透明点击层处理交互。

优点：实现最快，静态截图容易对齐。

缺点：重复当前扁平截图的结构性问题；红点、更多菜单、可访问性和动态隐藏入口难以维护，因此不采用。

### 方案 C：引入 Cocos/Spine 运行时直接执行原版组件

优点：理论上可以保留商城动画和原版 Lua 结构。

缺点：当前应用是原生 Java 原型；为一个底栏恢复完整运行时会扩大包体和生命周期复杂度，远超本次范围，因此不采用。

## 4. 页面布局

坐标继续使用项目现有的 `1920×1080` 虚拟画布。

浙江原版使用 Cocos 左下角坐标。转换为 Android 左上角坐标后：

- 底栏左边：`x = 80`。
- 底栏宽度：`1300`。
- 底栏高度：`95`。
- 原版中心 `y = 87.5`，因此 Android 顶边为 `1080 - (87.5 + 47.5) = 945`。
- 每侧内边距：`10`。
- 每个入口槽位宽度：`160`。
- 分隔线高度：`42`，垂直居中。

布局从左向右：

| 索引 | ID | 标题 | 默认视觉 |
|---:|---:|---|---|
| 0 | 1001 | 商城 | 浙江原版商城纹理组合的静态图标，可显示红点 |
| 1 | 1027 | 装扮 | 浅金文字，可显示“新”标记或红点 |
| 2 | 1005 | 战绩 | 浅金文字，可显示红点 |
| 3 | 1002 | 活动 | 浅金文字，可显示红点 |
| 4 | 1017 | 分享 | 浅金文字，可显示红点 |
| 5 | 1021 | 背包 | 浅金文字，可显示红点 |
| 6 | 1018 | 邮件 | 浅金文字，可显示红点 |
| 7 | 1007 | 更多 | 浅金文字，可显示红点；控制二级菜单 |

文字遵循原版参数：

- 字号基准：`40` 虚拟像素。
- 颜色：`#E8C8B5`。
- 水平和垂直居中。
- 直接复用浙江原版 `cocosStudio/Common/Font/fangzhengcuyuan.TTF`，随 Android 应用打包并由底栏文字加载。

底栏位于游戏卡片和背景之上、好友面板之下。它不再覆盖从 `y = 795` 开始的整片旧底部区域，因此能恢复更多背景可见面积。

## 5. 资源处理

新增资源均从浙江大厅原始资源机械提取或组合，不重新绘制风格：

1. 从 `_Plist.png` 按 `_Plist.plist` 坐标提取 `Img_dl`、`Img_fgx`、`Img_redpoint`、`Img_tip_di` 和 `Img_x`。
2. `Img_dl` 和 `Img_tip_di` 作为可拉伸底板使用，保持圆角、描边和气泡尖角不失真。
3. 从 `zzb_jbdt_sc.png/.atlas/.json` 组合一张透明背景商城静态图标，内容只取原版购物车与“商城”标识，不引入其他风格素材。
4. Android 资源统一放到 `drawable-nodpi`，避免系统密度再次缩放。
5. 旧的 `lobby_bottom_controls.png`、`lobby_quick_start.png` 和 `lobby_more_popup.png` 可保留在资源目录，避免扩大删除范围；页面不再引用它们。

## 6. 交互设计

### 6.1 主底栏

- 每项均有完整 `160×95` 点击区域。
- 每项设置对应中文内容描述。
- 点击采用项目现有原型策略：
  - 商城、装扮、战绩、活动、分享、背包、邮件：当前 Android 原型没有对应完整页面，点击显示同名提示，不伪造业务流程。
  - 更多：切换浙江样式二级菜单。
- 点击非“更多”入口时，如果二级菜单已打开，先关闭二级菜单，再执行入口提示。

### 6.2 更多菜单

- 从“更多”槽位上方向左展开。
- 使用 `Img_tip_di` 九宫底板，保留原版向下尖角。
- 菜单内容严格按浙江原版 `MenuBarID = 6` 当前可见项排列：计分助手、公众号、浙江新闻、绑定手机、设置、规则、健康须知、公告。原版标记为默认隐藏的“邀请”和标记为停用的防赌博入口不显示。
- 现有 Android 原型没有这些业务页时，点击显示同名提示并关闭菜单。
- 再次点击“更多”关闭菜单。
- 点击菜单以外的首页区域关闭菜单；不阻断游戏卡片和好友面板原有点击行为。
- 页面重建时菜单默认关闭。

### 6.3 红点与“新”标记

- 模型支持每个入口单独显示红点。
- 本次没有后端未读状态来源，默认所有红点关闭。
- 不硬编码伪造未读数量。
- 装扮的“新”标记同样默认关闭；后续接入状态时只需要更新模型，不修改布局。

## 7. 代码结构

保持最少改动：

- 新增 `LobbyBottomBarModel`：
  - 定义入口 ID、标题和顺序。
  - 定义 1920×1080 下的底栏矩形、槽位矩形和更多菜单状态切换。
  - 不依赖 Android UI，便于单元测试。
- 在 `MainActivity` 中新增少量底栏渲染辅助方法：
  - 创建底板、文字入口、商城图标、分隔线和点击层。
  - 创建并控制更多菜单。
  - 复用现有 `BoxRoot` 坐标适配和 toast 方法。
- 删除 `showLobbyPage()` 对旧底栏图、旧快速开始图和旧更多弹层的调用。
- 删除该页面对旧“快速开始”和旧“商城/更多”透明点击区域的绑定。
- 不修改登录、认证、好友系统、游戏入口、图标动画或后端代码。

不创建通用组件框架、主题系统或动态配置解析器；当前只有一个确定的底栏实例，直接的数据模型和渲染方法足够。

## 9. 非目标

- 不恢复 Cocos2d-x、Lua 或 Spine 运行时。
- 不实现浙江原版商城、装扮、战绩、活动、分享、背包、邮件等完整业务页面。
- 不接入后端红点、未读邮件或活动状态。
- 不修改首页上半部分、登录流程、游戏列表内容或好友面板。
- 不顺手重构 `MainActivity` 的其他既有代码。

## 10. 风险与处理

- 商城原版为 Spine 动画：使用原始纹理组合的静态图标，确保风格正确并避免运行时依赖。
- 原版字体文件已确认是可读取的 TrueType 字体；实现中直接从浙江资源复制并加载，加载失败属于验证失败，不静默切换成另一种视觉字体。
- 旧底栏图仍包含首页背景的一部分：移除旧图后若露出接缝，以现有 `lobby_bg.png` 为底，不重新修改上方游戏卡片资源。
- 绝对坐标适配：所有数值先在纯模型中定义，再由现有 `BoxRoot` 按项目统一方式缩放，避免在多个视图中重复换算。
